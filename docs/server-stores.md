# What the server stores

This note is for the privacy track. It lists what the server code in this repository writes, how long that data stays, and what stays on the device. It does not list the NEAR contract fields. The contract stores account ids, organization names, roles, and public encryption keys. It stores hashes, scope, expiry, status, and open counters. It emits NEP-297 events. It does not store chart text, and schema 2 has no `get_timeline`.

The server can store encrypted blobs. `PUT /api/blob` accepts bytes and `web/lib/blob/store.ts` stores them. The helper writes the bytes into the memory of that process. It also writes a file. The directory is `BLOB_DIR` when that name is set. Otherwise the directory is `.data/blobs` under the working directory. The helper does not parse the bytes and it does not write a separate plaintext copy. Nothing in the helper sets an expiry or deletes a file. A body over one million bytes is rejected (`BLOB_MAX_BYTES`). An empty body is rejected. A later open on another hosted function does not see that file. The browser keeps the ciphertext in session storage and sends it again on open. The open route can decrypt a demo envelope with `DEMO_ENC_SEED` and return the text in that response. It does not write that text to Redis or to the blob store. The log line is the status and the elapsed time.

Upstash holds counters when it is configured. The spend stop uses `KV_REST_API_URL` and `KV_REST_API_TOKEN`. The spend code also accepts `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`. The stored value is one integer of micro-USD. The key is the deployment environment, then `nearai:spend-micro`. A positive charge sets that key to expire after 400 days (`SPEND_TTL_SECONDS` in `web/lib/tee/spend.ts`). The value is a counter. It is not chart text. The same Redis holds support rate limits for 10 minutes. Those windows allow 12 creates for an address (`SUPPORT_IP_LIMIT`) and 6 creates for a wallet (`SUPPORT_WALLET_LIMIT`). Without Redis, the spend counter stays in the memory of one process.

Support tickets live in that same Redis. Each ticket expires 30 days after the last write (`SUPPORT_RETENTION_MS`). A ticket holds an id and the wallet account id. It holds a subject, a message, and a reply. It also holds a status and timestamps. The subject is capped at 120 characters. The message and the reply are capped at 2000 characters. A create is refused when the subject or the message matches the personal-identifier check. A create nonce expires after 10 minutes. Outside local development the support route returns 503 when Redis is not configured. No email address is collected.

Rate limits use Runtime Cache and process memory. Sign calls and NEAR AI calls use a Vercel Runtime Cache namespace named `rr-guard`. An address key keeps timestamps for 10 minutes. A daily counter lasts until the next UTC midnight plus 60 seconds. The cache is regional and a later read can miss. Ask TendAI uses a separate namespace named `rr-assist`. It keeps a daily count. It keeps a per-address daily count, and the address is part of that key. It keeps a per-session count for 12 hours. Those values are counts. The question text is not written there. Demo config limits live in process memory for 60 seconds. That key is a hash of the client address. Open calls keep an address key in process memory for 60 seconds. A preview-only check keeps two timestamps for 10 minutes. Production returns before that write.

Session state is a cookie plus process memory. The server does not keep a session database. It sets an HttpOnly cookie named `rr_visitor` for 12 hours. The cookie holds a session id and record ids. It holds share ids and receipt hashes. It holds a patient account id, a funding transaction id, and an encryption public key. It does not hold chart text. A summary receipt inside that cookie expires after 10 minutes. The instance that signed also keeps spent receipt hashes in its own memory for the life of that process. An open nonce is kept in that memory for 120 seconds. The nonce key is the share or record, the account id, and a hash of the nonce.

The summary call sees chart text and does not store it. `POST /api/tee/summary` receives the chart text in the request body before the server sends that text to NEAR AI Cloud. The handler does not write that text to Redis, the blob store, or the log. The log line is the status and the elapsed time. `POST /api/tee/deid` does not read a caller chart. It uses the built-in fictional fixture, seals the result, and may write that ciphertext through the same blob helper.

Some secrets never leave the browser. A local device key is saved only in the IndexedDB database `tendai-demo-key`. That record holds the NEAR secret and the X25519 secret. The page signs with them. The request does not include the secret. A wallet connected with near-connect keeps its key in the wallet. The app receives the account id and the signature. The Guided Demo does not use that path for clinic staff. Those actions use keys that already live in server environment variables.
